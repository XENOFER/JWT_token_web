JWT cheat sheet

The essentials on one page — structure, claims, algorithms, and the security rules that prevent most incidents. Bookmark it.

Structure

header.payload.signature
Header — alg, typ, sometimes kid Payload — the claims Signature — over header.payload

Each part is Base64URL (encoding, not encryption). JWS = signed, 3 parts · JWE = encrypted, 5 parts.

Security do & don't

Do
  • Verify — never just decode
  • Pin the algorithm(s)
  • Validate exp, aud, iss
  • Use long, random secrets / keys
  • Keep access tokens short; rotate refresh tokens
  • Store keys in a vault; rotate them
  • Prefer HttpOnly + SameSite cookies
Don't
  • Trust alg from the token
  • Accept none
  • Put secrets/PII in the payload
  • Use weak or hard-coded secrets
  • Trust token-supplied keys (jku/jwk)
  • Make access tokens long-lived
  • Catch verification errors and continue

Secure verification

const claims = jwt.verify(token, KEY, {
  algorithms: ['RS256'],                 // pin — defeats none & confusion
  issuer:   'https://auth.example.com',  // iss
  audience: 'https://api.example.com',   // aud
});                                       // exp / nbf enforced; throws on failure
