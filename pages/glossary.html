Glossary

Every term used across the academy, defined in a line. Jump by letter, and follow the links to the chapter that covers each idea in depth.

ABCDEHIJKNOPRST
A
Access token
A short-lived token presented on each request to reach protected resources. See Auth Flow.
Algorithm (alg)
The signing or encryption method named in a token's header, e.g. HS256 or RS256. See Algorithms.
Assertion
A package of claims about a subject, presented to a relying party; a JWT is one form of assertion.
Asymmetric
Cryptography using a key pair — a private key signs, a public key verifies.
Audience (aud)
The intended recipient of a token; a verifier rejects tokens not addressed to it.
Authentication
Establishing who a party is — distinct from authorization.
Authorization
Determining what a party is allowed to do.
B
Base64URL
A URL-safe, fully reversible text encoding used for a JWT's parts. It is encoding, not encryption. See Structure.
Bearer token
A token usable by whoever holds it, with no additional proof of identity required.
C
Claim
A single statement (key/value) inside a token's payload, such as sub or role. See Structure.
Confirmation (cnf)
A claim that binds a token to a holder's key, used by DPoP and mTLS. See DPoP.
D
DPoP
Demonstrating Proof-of-Possession — binds a token to a client's key so a stolen token alone is useless. See DPoP.
E
ECDSA (ES256/384/512)
Elliptic-curve signatures — small, fast, asymmetric. See Algorithms.
EdDSA
Modern Edwards-curve signatures; fast, deterministic, and misuse-resistant.
Expiration (exp)
The Unix time after which a token must be rejected.
H
Header
The first JWT segment, declaring the algorithm (alg) and type (typ).
HMAC (HS256/384/512)
A symmetric keyed-hash signature using a shared secret. See Algorithms.
I
ID token
An OpenID Connect JWT that asserts a user's identity to an application. See OpenID Connect.
Introspection
Asking the issuer whether an (opaque) token is currently valid — RFC 7662. See Alternatives.
Issued At (iat)
The time at which a token was created.
Issuer (iss)
Who created and signed a token; verified against an allow-list.
J
JOSE
The family of JSON object signing and encryption standards (JWS, JWE, JWK, JWA).
JTI (jti)
A unique token identifier, useful for revocation lists.
jku
A header naming a URL for the key set — dangerous if trusted from the token. See Vulnerabilities.
JWA
JSON Web Algorithms — the algorithm registry (RFC 7518).
JWE
JSON Web Encryption — an encrypted token with five parts. See JWE.
JWK
JSON Web Key — a single key represented in JSON.
JWKS
JSON Web Key Set — a published set of public keys. See JWKS.
JWS
JSON Web Signature — a signed token with three parts; the everyday "JWT".
JWT
JSON Web Token — a compact, signed (or encrypted) set of claims. See What is a JWT?
K
kid (Key ID)
A header identifying which key signed the token; treat it as an opaque lookup. See JWKS.
N
Nonce
A one-time value (e.g. in OIDC) preventing replay; the ID token echoes it back. See OpenID Connect.
Not Before (nbf)
The time before which a token is not yet valid.
O
OAuth 2.0
An authorization framework for granting delegated access. See OAuth vs JWT.
OpenID Connect (OIDC)
An authentication layer on top of OAuth 2.0 that issues ID tokens. See OpenID Connect.
Opaque token
A reference token with no readable contents, validated by introspection. See Alternatives.
P
PASETO
A safer JWT alternative with versioned, pinned cryptography. See Alternatives.
Payload
The second JWT segment, holding the claims.
PKCE
Proof Key for Code Exchange — protects the OAuth authorization code from interception. See OpenID Connect.
Private claim
A custom claim agreed privately between parties, e.g. role.
Public claim
A custom claim namespaced (often as a URI) to avoid collisions.
R
Refresh token
A long-lived token exchanged for new access tokens. See Auth Flow.
Registered claim
A standard claim defined by the spec: iss, sub, aud, exp, nbf, iat, jti.
Replay attack
Re-sending a captured token to impersonate its owner. See Vulnerabilities.
RSA (RS256/384/512)
Widely-supported asymmetric signatures with large keys and signatures.
Rotation
Periodically replacing signing keys (or refresh tokens) to limit blast radius. See JWKS & Rotation.
S
Scope
An OAuth permission string limiting what an access token can do.
Session
Server-side authentication state referenced by an opaque cookie ID. See Sessions vs JWT.
Signature
The third JWT segment, proving integrity and authenticity.
Subject (sub)
The principal a token is about, e.g. a user ID — the durable identifier to key accounts on.
Symmetric
Cryptography using one shared secret to both sign and verify.
T
Token exchange
Trading one token for another with different scope or audience — RFC 8693. See Service-to-Service.
typ
A header field declaring the token type, usually "JWT".
